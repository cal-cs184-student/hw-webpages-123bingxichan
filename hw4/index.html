Overview

In this project I implemented a cloth simulator using a mass-spring model. The cloth is represented as a grid of point masses connected by structural, shearing, and bending springs. Each simulation step accumulates external forces, spring forces, Verlet integration, spring length correction, collision response, and self-collision correction. I also implemented the shading portion of the assignment, including diffuse shading, Blinn-Phong shading, texture mapping, bump mapping, displacement mapping, and mirror shading. The main lesson was that the visual quality depends on both the physics parameters and the rendering model: high stiffness can reduce stretching but can introduce jitter, while shader effects such as bump mapping can add detail without changing geometry.

Representative cloth result
The most interesting technical challenge was self-collision. A direct all-pairs check would be too slow, so I used spatial hashing to only compare point masses that land in the same local box.

Part 1: Masses and Springs

I built the cloth as a row-major grid of point masses. For horizontal cloth, each mass lies in the x-z plane with a fixed y value; for vertical cloth, each mass lies in the x-y plane with a small random z offset so the cloth does not begin perfectly flat. The pinned list from the scene file marks which masses should stay fixed. After creating the masses, I connected neighboring masses with springs: structural springs connect immediate horizontal and vertical neighbors, shearing springs connect diagonal neighbors, and bending springs connect masses two grid steps apart horizontally or vertically. These springs store their rest lengths at construction time, which are later used by Hooke's law and the Provot length constraint.

Part 2: Simulation via Numerical Integration

For each simulation step I first compute the total external force on each point mass, mainly gravity scaled by the mass of a grid point. Then I add spring forces using Hooke's law. Bending springs use a weaker stiffness, 0.2 times the main stiffness, because they are meant to resist folding gently rather than make the cloth rigid. I update positions with Verlet integration: the new position depends on the current position, previous position, damping, and acceleration over the time step. Pinned masses are skipped. After integration, I apply collision handling and then enforce Provot's constraint so no spring can stretch beyond 110 percent of its rest length in a single step.

Low ks makes the springs weaker, so the cloth stretches and sags more before settling. High ks makes the springs resist stretching more strongly; the cloth holds its shape better, but the motion can look more energetic or jittery because the forces become much larger.

Increasing density gives each point mass more mass, so gravity has a stronger visual effect and the cloth tends to sag more deeply. Lower density makes the cloth feel lighter, with less pronounced sag. Damping controls how quickly motion dies out: low damping lets the cloth swing and oscillate for longer, while high damping makes it settle much faster.

Part 3: Handling Collisions with Other Objects

For sphere collisions, I check whether a point mass has moved inside the sphere by comparing its distance from the sphere center to the sphere radius. If it is inside, I project it back to the sphere surface along the radial direction and apply friction by moving only part of the correction from the previous position. For plane collisions, I check whether the point mass crossed the plane between its last position and current position. If it crossed, I compute the intersection point along that path, offset it slightly away from the plane to avoid numerical sticking, and again scale the correction by friction.

Part 4: Handling Self-Collisions

I implemented self-collision using spatial hashing. At the beginning of the self-collision pass, each point mass is placed into a hash bucket based on a 3D box around its position. The box dimensions are based on the cloth grid spacing, with depth set to the larger of the width and height bucket sizes. For each point mass, I only compare it against other point masses in the same bucket. If another point mass is closer than twice the cloth thickness, I compute a correction vector that pushes the current mass away until the pair is separated by the minimum allowed distance. I average all corrections for that mass and divide by the number of simulation steps, which keeps the correction gradual and stable.

Part 5: Shaders

A shader program controls how geometry is drawn on the GPU. The vertex shader runs once per vertex and is responsible for transforming positions into screen space while passing data such as world-space position, normal, tangent, and UV coordinates to the next stage. The fragment shader runs for each pixel covered by a triangle and computes the final color. In this assignment, the vertex shader handles transforms and displacement, while the fragment shaders implement lighting, texture lookup, bump-mapped normals, and environment reflection.

Blinn-Phong Components

Blinn-Phong shading combines ambient, diffuse, and specular lighting. Ambient lighting is a small constant term that keeps shadowed areas from becoming completely black. Diffuse lighting models matte reflection and depends on the angle between the surface normal and the light direction. Specular lighting models shiny highlights. Instead of reflecting the light vector directly like classic Phong shading, Blinn-Phong uses a halfway vector between the view direction and the light direction, then raises the normal-halfway dot product to a shininess exponent. The final shader output is the sum of these three terms.

Texture, Bump, Displacement, and Mirror

Texture mapping samples an image using the interpolated UV coordinate and uses that sampled color as the material color. Bump mapping uses a height texture to perturb the surface normal in tangent space, which changes the lighting and creates the appearance of small surface detail without moving any vertices. Displacement mapping uses the same idea but actually moves vertices along their normals in the vertex shader, so the silhouette and geometry can change when the mesh is dense enough. Mirror shading uses the view direction and surface normal to compute a reflection vector, then samples the cubemap in that reflected direction.

With the fine -o 128 -a 128 sphere, displacement mapping becomes much more convincing because the mesh has enough geometry for the height map to create actual shape changes.
